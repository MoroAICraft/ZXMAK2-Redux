# v93 PSG Noise Zero TEST — на основе v92

Дата: 2026-11-01. Статус: отдельная тестовая сборка, приёмка пользователем ещё не выполнена.

## База и изменение

База — `codex/prefinal-v92`, коммит `72eb747621106f996d72a4bd573374a390665799`.
OmniSound закреплён на `726c63d7cb00275aff7975eaac3687405568be74`.
Все функции v92 сохранены. Исходный репозиторий на L: и установленная
`D:\release_92_extreme_drop` не изменялись; разработка выполнялась в
`D:\ZXMAK2_Work\psg_noise_zero_v93_20261101\source`, ветка `codex/psg-noise-zero-v93`.
Оригиналы музыки/рабочих носителей/AY Emulator и OmniPlayer не изменялись.

Единственное изменение продуктового кода:
`src/ZXMAK2.Hardware.Circuits/Sound/PsgChip.cs`, обработка R6 в timed SetReg:

```diff
-                    m_divN = value*2;
+                    m_divN = Math.Max(1, (int)value) * 2;
```

Причина: условие `++m_cntN >= m_divN` с нулевым делителем обновляло шум
каждый внутренний такт вместо каждого второго. Нормализуется только внутренний
делитель. Записанный R6=0 читается как 0; маска 31 сохранена. Записи не сбрасывают
счётчик или последовательность, обработка до момента записи остаётся со старым
периодом. Reset сохраняет прежнюю семантику фазы, но корректно выставляет делитель 2.

Не менялись тон, огибающая, таблицы амплитуд, частоты, панорама, громкость,
ресемплер, фильтры, FM/OPL/SAA/MIDI/GS и музыкальные движки. Никаких исключений по
файлу/формату/плате. `NoiseExperiment` не использовался при проверке новой DLL.

## Проверки ядра и двоичной совместимости

Исходная DLL из чистого v92 совпадает с установленной пользовательской DLL.
Отдельно собранный из текущего HEAD исходный код воспроизвёл тот же дефект.

| R6 | v92: шагов шума за 64 внутренних такта | v93 |
|---|---:|---:|
| 0 | 64 | 32 |
| 1 | 32 | 32 |
| 2 | 16 | 16 |
| 3 | 10 | 10 |

`PsgNoiseZeroProbe`: 429873 утверждения, 1782 случая переходов/фаз/Reset.
Проверены обе перегрузки SetReg, конструктор без дополнительной записи R6,
повторные записи, маски 0x20/0x21 и readback, переходы между 0/1/31 при 66 фазах,
внеузловая граница записи внутри кадра, отсутствие сброса фазы/лишних обновлений.
Независимый счётчик/LFSR в тесте сверяет состояние после каждого шага, без записи
во внутренние поля. Последовательность и PCM для 0/1/0x20/0x21 совпадают.

Для AY8910, YM2149F и YM2203 на 1750000/1773400 Гц сравнивались 186 потоков
ненулевых периодов 1…31 по 4096 тактов, с тоном и огибающей, без предшествующего
рендеринга нулевого периода. Все совпали с v92; SHA256 таблицы результатов:
`333957BC706A9A5D7B03FF6DEB7BC5BD2BCEBB913D7C7B064164C9576DF62043`.
После участка R6=0 совпадение со старым ошибочным состоянием намеренно не требуется.

IL всех методов исходной поставляемой v92 и повторно собранной v92 совпал.
Между v92/v93 изменился IL ровно одного метода — timed PsgChip.SetReg.
Сигнатуры публичного API/сборки совпали. Поэтому достаточно заменить одну
`Lib/Managed/ZXMAK2.Hardware.Circuits.dll`; сборочная идентичность не менялась.
В полном runtime остальные EXE/DLL и ресурсы взяты побайтно из v92; изменена
только эта DLL, добавлена инструкция v93, инструкция базы перенесена в Docs.

SHA256 DLL:

- v92 поставляемая: `3F7C12CF1362FCF75A45BBC443891054B3109BDBDD89E1FEC19926BADA643B39`.
- v92 повторно собранная: `E2DD16FC9475C2D2FBFDDCFA7BE018764D72C23AA7D4B594D6253B71A6328D5A`.
- v93 поставляемая: `BD3AF72A63F1D80712C954C68D838676851878CCC665E37F9D97D3D4AFBDAFD6`.

Разные PE-хеши повторных сборок ожидаемы для этого старого недетерминированного
toolchain; для анализа поведения сравнивались IL, API и результаты исполнения.

## Реальные потребители общего PSG

`Config/unity.config` связывает IPsgChip с PsgChip. Прямые потребители:
AY8910 (в том числе наследник AYCHRV для внутреннего звука Evo) и
TsFmPsgRenderer. Последний используется двумя SSG в TSFM Pro, ZxMultiSoundCore
(MultiSound, Max, OmniSound) и Extreme Rev03. OmniSound наследует именно этот
SSG-тракт; его нативный FM не является отдельным PSG.

`PsgNoiseRoutesProbe` прошёл 12 маршрутов: по одному AY8910/AYCHRV и по два SSG
у пяти перечисленных плат. Тест пишет через реальный CPU.WRPORT и декодер платы,
сверяет внутренний делитель/readback и 12 кадров выходного PCM/последовательности:
0 == 1 == 0x20, отличны от 2. Это адресные проверки в sandbox с Z80/ULA;
не отдельный полный запуск NedoOS на каждой плате.

Дополнительно штатный Test.exe прошёл `/tsfm`, `/multisound`, `/multisoundmax`,
`/omnisound`, `/master-volume`, включая FM/SSG/таймеры/OPL и SAA-регрессии,
которые входят в эти сценарии. Проверка общего ядра не означает изменения
MoonSound/OPL4, SAA1099, MIDI, GS или всех возможных машин.

## Полный гостевой запуск

Исполнялись оригинальные ROM, NedoOS и неизменённый OmniPlayer **139P YV1**,
MultiSound, SSG 1750000 Гц, 44.1 кГц, CPU multiplier 4. Только отдельные копии
SD и read-only частный HDD; sandbox не подключает пользовательские носители.
Исходный azimuth.pt3 — 3117 байт,
SHA256 `1842C2D02A00E10416125CC8416D77609311F0ACD9FF3361503E25295954C89D`.

В полном проходе до/после:

- 60657 общих записей PSG совпали по порядку, данным, кадру, такту CPU и PC.
- 56314 музыкальных записей совпали с готовым независимым эталоном; 4320 тактов,
  кадры 1664…5983, все 4319 интервалов равны одному кадру. NEXT/STOP — кадр 5984.
- В новую DLL поступали исходные нули R6: зафиксированы 2202 записи. Никакой
  внешней подмены 0→1 не было.
- По 6614 кадров, 3792732193 такта CPU, 5833548 стереоотсчётов; зависаний нет.
- Общий raw.io/CPU-снимок всей загрузки не идентичен: первый отличающийся байт
  — чтение SD #F257 на кадре 41 (FB/52). Частные носители создавались отдельно.
  Поэтому не заявляется побайтное совпадение всей загрузки/R-регистра CPU.
  Музыкальные команды и их точные времена совпали; в отдельном сценарии
  управления/подборки совпал и полный файл контрольных CPU-снимков.

В адресном сценарии проверены P-пауза/продолжение, Esc-остановка, Right-переход
на dual.pt3. На паузе elapsed=74 не менялся, PCM нулевой; после продолжения
таймер двигался и PCM ненулевой; после остановки PCM нулевой.
Два дополнительных PT3 (Siril_5 / version 3 и version 7/table 1), составной
TurboSound Dizzy Ring of Zaks, ASC BREED!, FXM Alla Turca запущены без изменения
плеера. 30828 записей PSG в адресном сценарии совпали до/после, включая времена.
Подборка короткая, не проверка всех файлов каждого формата.

## Аудио и границы вывода

В `audio` — исходные 15-секундные WAV до/после при одинаковых настройках и
временах (примерно 1.5…16.5 секунды «Азимута»), плюс версии для прослушивания.
В последних вычтено постоянное среднее каждого канала и применён один общий
коэффициент до RMS 2000; нет EQ/шумоподавления/динамической обработки.
Это обработка файлов сравнения, НЕ новый фильтр эмулятора.
`diagnostics/audio.json` содержит коэффициенты и хеши.

03/04 — сохранённые эталонные рендеры из авторских исходников AY Emulator 3.0,
не новый экспорт из пользовательского Windows-приложения. Пользовательский
эталон: YM/1773400/ABC/48k/FIR; приближённый: YM/1750000/CBA/48k/FIR.
Исходники/хеши независимого исследования остались на D: в
`OmniPlayer_Workspace/work/pt3_ayemul_20261101`. AYumi также нормализует только
шумовой период до >=1 и удваивает его в счётчике.

Не выполнены и не заявляются: слуховая приёмка пользователем, реальное железо,
полное тождество AY Emulator, все машины/форматы/частоты CPU, проверка задержек
Windows-аудио и полноценный ручной обход desktop GUI. Новая тяжёлая обработка
аудио не добавлена. Ошибки на настоящей плате этим исправлением не устраняются.

## Комплект, сборка, установка и откат

В выдаче: `release` (полный v92+fix, без рабочих носителей), Full/Clean ZIP,
`patch/Lib/Managed` (одна DLL), `rollback` (оригинальная DLL v92),
`source` (исходники с закреплённым OmniSound, история Git, patch), `repro`
(стенд и частные входные данные), `diagnostics`, `audio`, контрольные суммы.
Большие raw.io остаются в рабочем каталоге D:, их хеши указаны в diagnostics.

Безопасная проверка: распаковать полный комплект в НОВУЮ папку на доступном
для записи диске, подключить только копии носителей. Альтернатива — сделать
копию своей v92 и заменить в ней только DLL из `patch`. Не перезаписывать
VMZ/CMOS/VMIDE/NVRAM/Config чужими настройками. Патч не предназначен для
произвольной старой/новой сборки; перед заменой сверить исходный хеш выше.
Откат: закрыть тестовый экземпляр и вернуть DLL из `rollback`, либо запустить
нетронутый v92. Автоматической установки/изменения рабочей копии нет.

Сборка из корня исходников на D: (.NET Framework 4 Client, MSBuild VS2022):

```powershell
& 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\MSBuild.exe' `
  src/ZXMAK2.Hardware.Circuits/ZXMAK2.Hardware.Circuits.csproj `
  /t:Rebuild /p:Configuration=Release /p:Platform=AnyCPU /m:1 /v:quiet /nologo
```

Результат: `src/_binrelease/ZXMAK2.Hardware.Circuits.dll`.
Для повторения ядра/маршрутов — `tools/SoundCards/RunPsgNoiseZero.ps1` с
`-BaselineRuntime` (чистый v92) и `-Work` (новый каталог на D:). Скрипт проверен.
Гостевые скрипты сохранены с точными путями стенда; при переносе стенда необходимо
обновить две защитные границы private SD в DurationProbe.cs и конфигурацию,
не направлять их на установку/рабочие носители. См. `repro/README.txt`.

Исходники/сборки предыдущих версий не удаляются. Публикации на GitHub нет.
Дальнейший переход к v93 — только после подтверждения пользователя.
