# v94 NMI Prefix TEST на базе v93

Дата: 2 ноября 2026. Отдельная тестовая сборка. **Рабочей базой остаётся v93
до подтверждения пользователя.** Print Screen уже был назначен на NMI;
назначение клавиши и её область действия не менялись.

## Причина и исправление

Z80Cpu.ExecCycle обрабатывает префикс и продолжение инструкции отдельными
вызовами. ProcessSignals раньше принимал NMI между ними: например, после ED
переходил на 0066, складывал в стек адрес продолжения и сохранял XFX=Ed.
Байт обработчика NMI мог интерпретироваться как продолжение прерванной команды.

По [руководству Zilog UM008011-0816, стр. 6](https://www.zilog.com/docs/z80/um0080.pdf)
NMI принимается по окончании инструкции. В v94 при активном FX/XFX запрос
запоминается и обрабатывается после завершения команды. Одной проверки
границы недостаточно: EventManager выдаёт обычный запрос на один ExecCycle,
а затем сбрасывает вход NMI. Новый закрытый флаг сохраняет такой запрос
до ACK; RESET его отменяет. Существующее подавление INT после EI не
распространяется на NMI: BINT для новой проверки не используется.

Единственный изменённый продуктовый файл:
`src/ZXMAK2.Engine.Cpu/Processor/Z80Cpu.cs`.
Публичный API CPU и идентичность сборки прежние. В runtime заменена только
`Lib/Managed/ZXMAK2.Engine.Cpu.dll`; остальные EXE/DLL, прошивки, банки и
настройки побайтно взяты из закреплённой v93. README v93 перенесён в Docs,
добавлены README v94 и этот отчёт. Изменение PSG из v93 сохранено.

Не менялись BC Commander, клавиатурный маршрутизатор, логика платы BaseConf,
EventManager, звук, SD, сохранение папок, файловые ассоциации и конфигурации.
Новых глобальных перехватчиков клавиатуры нет.

## Подтверждение

| Проверка | v93 | v94 |
| --- | --- | --- |
| ED 44 по адресу 8000, NMI после ED | ACK: PC=0066, XFX=Ed, стек=8001 | NEG завершается; стек=8002; ACK +11T; FX/XFX=None |
| Native BC, ED 00 заканчивается перед A100 | ACK при PC=A0FF, XFX=Ed | ACK при PC=A100, FX/XFX=None; меню и возврат работают |
| Короткий запрос через настоящий EventManager | Прерывает префикс | Ожидает завершения команды, не теряется |

`NmiPrefixProbe`: **261 случай, 12497 проверок**, без ошибок на v94;
все 261 случая обнаруживают дефект v93. Четыре типа CPU; ED, CB, DD, FD,
DDCB/FDCB, повторные/смешанные префиксы, игнорируемые префиксы,
неопределённый ED, LDIR между итерациями, prefixed HALT/EI, длинная цепочка,
импульсный и удерживаемый запрос. Проверены стек, PC, эффекты команды,
11T входа NMI, R, RETN, отсутствие повторного ACK, обычный NMI,
приоритет относительно INT/RESET, сброс отложенного запроса и задержка INT
после EI. Это не полная новая сертификация всех тонкостей Z80.

Исполняемый архивный **BC Commander v0.63**, ROM BaseConf, SD-контроллер и
реальный двоичный обработчик: **18 префиксных сценариев** (6 семейств ×
3,5/7/14 МГц). Меню открывается, Escape возвращает PC, основные и
альтернативные регистры, SP/R/IM/IFF, paging и содержимое восьми RAM-банков
(за исключением двух байтов, занятых стеком входа NMI).
Ещё четыре сценария ordinary/48K/IFF enabled/48K+IFF enabled проходят
на обеих версиях. Старые двоичные файлы BC не исправлялись; изменена только
копия диагностической оболочки, чтобы запрос попадал внутрь инструкции.
Все тестовые носители — копии, SD в этих тестах открыт только для чтения.

Полный `RunRegressions.ps1` прошёл: PrintScreen KEYUP/down/hold/disabled,
F10/F12/маршрутизация клавиш, IRQ/NMI/WAIT, видеотайминги и golden-рендереры,
лента, SD SPI (6184), Refresh (157), закрытие/сохранение сессии (22),
MoonSound, OmniSound, MultiSound Max, OPL, громкость, дисплей и Test.exe.

**Все 10 контрольных CPU/RAM/видео/PCM/I/O отпечатков совпали с v93**:
Spectrum 48/128, три снимка, Evo 3,5/7/14 МГц и переключения машин.
Публичный API совпал. Сырые IL-хеши некоторых неизменённых методов различаются
из-за сдвига metadata tokens при добавлении поля; это не отдельные правки
алгоритмов. Проверки поведения и исходный diff сохранены отдельно.

Ограниченный benchmark, 10 измерений каждого сценария, порядок
v93/v94 затем v94/v93, одна и та же привязка тестового процесса к CPU:
изменение медиан −1,77…+0,70%; CPU-only 243 → 243,5 мс (+0,21%).
Заметного замедления в этих тестах не выявлено; это не обещание нулевой
разницы на любом компьютере. Настройки приоритета/affinity runtime не менялись.

`-Runtime <release> -FixtureArchive <diagnostics/native-fixture.zip> -Work <новый каталог>`.
Он сам копирует runtime/fixture и не запускается в установленной папке.
Не выполнять бесконечные режимы Test.exe `/perf` или `/cpu`.

## Проверка пользователем и откат

Распаковать Full или Clean ZIP в **новую доступную для записи папку**.
Full сохраняет настройки базового комплекта v93, Clean не содержит активных
CMOS/VMZ/VMIDE/NVRAM. Для проб подключать копии носителей; запомненные Full
пути могут указывать на прежние внешние папки. Установленный `D:\release_93`,
рабочие носители и исходники BC Commander не изменялись. GitHub не обновлялся.

Откат: прежняя установка v93 либо полный неизменённый v93 ZIP в `rollback`.
Не смешивать DLL разных комплектов. Старые сборки не удалялись.

Не выполнены: ручное физическое нажатие Print Screen в desktop-сеансе с
актуальной пользовательской версией BC, длительный игровой прогон, проверка
реального ZX Evolution и всех возможных машин/снимков. Скриптовый маршрут
PrintScreen → команда NMI и native BC вход/возврат проверены отдельно,
это не выдаётся за единый ручной UI-тест. Нужна приёмка пользователя.
