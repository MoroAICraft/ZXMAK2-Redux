## Причина дубликатов и исправление

Прежний `RegisterAt` строил ProgID как `ZXMAK2.Portable.<SHA256 пути EXE>`.
Каждая новая распаковка давала отдельный пункт. Теперь идентификатор один:
`ZXMAK2.Portable`, команда `"<EXE>" --open-with "%1"`.

Запуск через Windows проходит диспетчеризацию ДО instance.lock, Logger,
Locator, конфигурации и создания машины. Один совместимый экземпляр получает
файл; несколько — окно выбора папки/полного пути; ни одного — обычный запуск
зарегистрированной копии. Последняя копия обновляется только при успешном
показе нормально запускаемого окна, а не при промежуточной передаче файла.
Прямой EXE, File/Open и drag/drop остаются локальными. Настройки не объединяются.

Доступны только TRD/SCL/TAP/SNA из прежней регистрации. Дальнейшую проверку
формата, выбор дисковода, замену носителя и сохранение изменений выполняют
прежние загрузчики выбранной машины. Сам диспетчер ничего не записывает в носители.

Обнаружение — процессы того же имени, текущей Windows-сессии, с живым v2-маркером
и ответом именованного канала. SID/SessionId/PID/время старта разделяют экземпляры;
ACL разрешает текущего пользователя. Маркер исчезает после завершения процесса.
Нет службы, глобального перехвата клавиш или постоянного сканирования процессов.
Рабочий поток ждёт канал; перечисление происходит только при запросе открытия.

Протокол ограничен по времени и размеру, очередь — 32 файла. Идентификаторы
последних 256 запросов защищают от повторной постановки одного запроса.
ACK означает «принято в очередь», НЕ «успешно загружено». При тайм-ауте нет
автоматической повторной отправки или переключения на другую VM. Вновь запустить
нужно осознанно: после потери ACK результат может быть неизвестен. Это не обещание
сохранения очереди после аварии или перезапуска процесса.

Меню/модальный диалог задерживают обработку очереди. Закрывающийся экземпляр
отклоняет новые запросы; отмена выхода возвращает приём. Уже принятая очередь
не выбрасывается при штатном закрытии: сначала нужно обработать запросы.
Не отвечающий v2-процесс не считается отсутствующим и не вызывает скрытый запуск другой VM.

## Реестр и переносимость

Изменения только HKCU. UserChoice, стандартное приложение расширения,
другие программы и OpenWithList/MRU не переписываются. Узнаём старую собственную
запись по имени/хешу пути, точному прежнему формату команды и описанию, а не по
отображаемому слову ZXMAK2. Повреждённые/чужие похожие записи пропускаются.

Перед изменением сохраняется точечный UTF-16 `.reg` с исходными значениями и
их типами в `Data/Backups/OpenWith`. Ошибка резервирования блокирует изменения.
Старые собственные ссылки в OpenWithProgids убираются, ProgID остаются скрытыми
переадресациями (`NoOpenWith`) для прежних ассоциаций. Сами EXE старых сборок не меняются.
Резервирование/повторная регистрация проверены на изолированных тестовых ветках HKCU,
включая реальный импорт файла отката через reg.exe. Пользовательский реестр Classes
в ходе проверки не изменялся; миграция произойдёт при первом обычном запуске v95.

Основание схемы регистрации: [Microsoft: Open With](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-include-an-application-on-the-open-with-dialog-box)
и [Application Registration / NoOpenWith](https://learn.microsoft.com/en-us/windows/win32/shell/app-registration).

Ограничения: старые v92–v94 не участвуют в маршрутизации v2 и могут вновь добавить
старые регистрации. Для выбора между двумя рабочими копиями обе должны быть v95.
После перемещения зарегистрированного EXE нужно запустить его из нового места:
Windows не сможет вызвать отсутствующий файл, даже если другая копия работает.
Удаление чужих/ручных записей и очистка произвольного кэша Проводника не выполняются.

## Изменённые файлы

- `src/ZXMAK2.Logging/PortableLaunch.cs`: IPC, обнаружение, очередь и маршрут.
- `src/ZXMAK2.Logging/PortableRegistration.cs`: регистрация, миграция и откат.
- `src/ZXMAK2/Program.cs`, `OpenWithDialog.cs`: ранний режим диспетчера и выбор.
- `src/ZXMAK2.Host.WinForms/Views/MainView.cs`: готовность окна, защита закрытия.
- Два соответствующих `.csproj`, справка, тесты `tools/OpenWith`, обновление
  ожидания стабильного ProgID в существующем `PrefinalProbe`.

В runtime заменены только `ZXMAK2.exe`, `Lib/Managed/ZXMAK2.Logging.dll`,
`Lib/Managed/ZXMAK2.Host.WinForms.dll`, справка/README. Остальные файлы базового
runtime сравниваются по SHA256 при упаковке, в том числе CPU с исправлением NMI,
hardware, native audio, ROM, банки, конфиги и Test.exe. Новых исправлений эмуляции нет.

## Выполненные проверки

- `OpenWithProbe`: **92 проверки**. Стабильная регистрация двух путей,
  повторный запуск, миграция, сохранение defaults/чужих записей, откат .reg,
  REG_NONE, ошибка backup, повреждённые записи; Unicode, очередь, дедупликация,
  закрытие/отмена, два настоящих процесса, выбор/Cancel, гибель/занятость адресата.
- Настоящий собранный `ZXMAK2.exe --open-with` передал файл другому процессу из
  чужого CWD. У диспетчера намеренно отсутствовали VMZ/ROM/нативные зависимости;
  папка Data не появилась: машина/настройки/журнал не запускались.
- `StartupProbe`: фактический Program.cs с подставным ILauncher — прямой запуск
  и старт при отсутствии адресатов, аргументы, отложенная регистрация, освобождение
  instance.lock. Это проверка оболочки, а не новый реальный прогон гостевой ОС.
- Окно выбора: построение и bitmap-проверка, разные полные пути, кнопка выбранного
  экземпляра. Изображение `diagnostics/chooser.png`.
- `PrefinalProbe`: **78 проверок**, штатные загрузчики TRD/SCL/TAP/SNA,
  выбор A/B/Cancel/save, modal/menu очередь, Ctrl+F, смена карт и сохранение носителей.
- Общий `RunRegressions`: PrintScreen/NMI (261 случая, 12497 assertions), клавиши,
  CPU/IRQ/WAIT, видео, лента, SD SPI (6184), Refresh (157), close/save (22),
  MoonSound/OmniSound/Max/OPL, master-volume, display, полный Test/ULA/benchmark.

Пробы выполнялись в частных копиях `D:/ZXMAK2_Work/open_with_v95_20261103`,
не в пользовательских установках. Внесённая после общего прогона дополнительная
защита от короткой повреждённой строки реестра повторно проверена новым набором
OpenWithProbe, Prefinal и Startup на окончательных двоичных файлах.

## Не выполнено / приёмка

Не выполнены реальные клики по меню Windows Explorer после миграции, запуск
через несколько учётных/RDP-сеансов или разные уровни UAC, перенос на другой
физический компьютер, ручной drag/drop и длительный игровой прогон v95.
Скриптовые проверки не выдаются за эти ручные проверки. Возможна задержка
обновления кэша Проводника; итоговый вид меню нужно подтвердить пользователю.

Проверить две распакованные копии: один пункт ZXMAK2, одно окно получает файл
без выбора; при двух можно выбрать по папке; Cancel ничего не меняет. Закрыть
обе — открывается последняя нормально запущенная копия. Перенести одну, запустить
вручную и повторить. Использовать тестовые носители; Full может хранить рабочие пути.
