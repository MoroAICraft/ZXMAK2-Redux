Что исправлено
==============
1. Частичное сохранение внутреннего SD IMG.
   Было: первый сектор записан, второй получает IOException; дата источника
   меняется собственной записью. Retry принимал это за внешнее изменение.
   Discard удалял redo-журнал, оставляя частично обновлённый образ.

   Теперь есть явное состояние начатого применения. После своей попытки
   обновляется fingerprint; следующая попытка всё ещё проверяет источник.
   Исходный stream в штатном пути держится с FileShare.Read, без доступа
   другого писателя. Общая проверка внешних изменений не удалена.
   До записи сохраняются журнал и marker; для FileStream применён Flush(true).
   Пока сохранение не завершено, новые гостевые записи отклоняются.
   Discard запрещён: повторный UI-вопрос содержит Retry / Cancel.
   Cancel отменяет выход/смену носителя и оставляет журнал; Retry заканчивает
   сохранение. После переоткрытия начатая транзакция завершается старым redo-
   механизмом до доступа гостя к данным. Это не откат уже записанных секторов.

   Очистка: отказ удаления самого journal сохраняет dirty/incomplete и retry.
   Отказ удаления оставшегося marker после удаления journal не маскирует
   успешное сохранение; новый journal не создаётся, пока старый marker нельзя
   удалить. Исключено связывание нового несохранённого сеанса со старым marker.
   При ошибке очистки journal внешнего IMG stream/путь остаются согласованными:
   переключение на внутреннюю копию происходит только после очистки.

2. Сохранение SD-папки и read-only.
   Было: read-only исходник переносился в backup, новый файл сохранялся,
   dirty очищался, затем удаление backup выбрасывало UnauthorizedAccessException.
   Пользователь видел ошибку, хотя данные уже были записаны.

   Теперь изменяемые/удаляемые read-only исходники проверяются до staging,
   затем непосредственно перед переносом. Сессия остаётся, источник не заменяется.
   Защита пользовательских файлов автоматически НЕ снимается.
   IOException/UnauthorizedAccessException при уборке собственных stage/backup
   не подменяют результат транзакции; журнал сообщает путь оставшегося каталога.
   Основной rollback при ошибках записи/пересборки сохранён.

3. Отказ звукового вывода Windows (DirectSound).
   Было: исключение завершало playback thread, IsSyncSupported оставался true;
   VM продолжала ждать неработающего потребителя до 40 мс на кадр.

   Теперь native device/buffer создаются и освобождаются потоком вывода.
   После исключения объявляется недоступность, разблокируется ожидание кадра,
   устройство/буфер пересоздаются с паузой в одну секунду между попытками.
   Watchdog при отсутствии уведомлений проверяет PLAYING/BUFFERLOST.
   Очереди остаются ограниченными; старые кадры сбрасываются при восстановлении.
   Каждый новый native-буфер полностью заполняется тишиной до запуска.
   Ошибка Stop не препятствует освобождению буфера/устройства.
   HostService при выбранной Sound-синхронизации временно использует TimeSync;
   выбранная настройка не меняется, Sound возвращается автоматически.
   Режим без синхронизации не замедляется. Фильтры, микшер, громкость, sample rate
   и штатное число/размер буферов не менялись; v83 HQ не возвращена.
