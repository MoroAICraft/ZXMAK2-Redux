## Причина и исправление

В отдельном аудите опубликованной v87 подтверждены ошибки старого
`TsFmFmRenderer`: feedback не обновлялся в алгоритмах 4–7; неверная топология
алгоритмов 2/3; игнорирование DT и KS; упрощённые огибающие, частотные регистры
и отсутствующие таймеры/BUSY. Это не доказательство компрессора или обрезанной
АЧХ общего выхода. Поднимать высокие частоты/громкость вместо исправления
синтеза не стали. Аудит сохранён отдельно в `ZXMAK2-SoundCards-Audit-v87-20261010`.

Пользователь отдельно подтвердил замену на ymfm с проверками. Все четыре
карты теперь создают `Ym2203FmRenderer`: два независимых YM2203 по 3,5 МГц.
Общие только код и неизменённая DLL; состояние каждой карты/чипа своё.

| Карта | Host-класс | FM / остальные выходы |
| --- | --- | --- |
| TurboSound FM Pro | TurboSoundFmPro | 2×YM2203 FM; прежние SSG и SAA |
| MultiSound A2 | ZxMultiSoundDevice | то же FM; прежние SSG/SAA/GS/SoundDrive/MIDI |
| MultiSound Max | ZxMultiSoundMaxDevice | то же FM; дополнительно прежний OPL3 |
| OmniSound | ZxOmniSoundDevice | тот же OPN; прежние OPL4/PCM/NeoGS и остальные блоки |

SSG по-прежнему звучит только через прежний PSG-рендерер: встроенный SSG
native-ядра в микшер не добавлен. Но его записи доходят до YM2203 для BUSY.
Адресные команды 2D/2E/2F меняют согласованно FM и SSG prescaler.
FM-регистры не читаются из программного shadow-cache; I/O A/B вызываются
только для 0E/0F, а не для всех FM-адресов, заканчивающихся E/F.

Аппаратные декодеры карт и их селекторы сохранены. В частности старый
TSFM status/output selector не переписан без новой проверки RTL; аналоговая
блокировка MultiSound не превращена в отключение таймера. Соседние SAA,
MIDI/GS, общий микшер, CPU, видео, клавиатура и SD/Tape не переделаны.
Отменённый тяжёлый FIR v83 не включён. MoonSound/flash/ENDOS не изменены.

Native `omni_opn.dll` не пересобиралась: это уже использовавшееся в OmniSound
ядро Aaron Giles ymfm, pinned `81aec25ccbb98f4873a255f7551ac4dadac59b4a`.
Его лицензия остаётся в `Docs/Licenses/omni-opn.LICENSE.txt`.
Старый управляемый FM-класс оставлен неактивным для диагностического контроля;
ни одна из этих четырёх карт больше не выбирает его в рабочем режиме.
У native FM собственный уровень выхода, а не механический старый +50% gain.

У Max обнаружено отдельное изменение высоты тона при host-rate не 44,1 кГц:
core всегда генерировал 44,1 кГц, host проигрывал их один к одному. Добавлен
ресэмплер с непрерывной фазой/историей между записями и кадрами. Прямой путь
44,1 кГц сохранён; принятый ресэмплер MoonSound не затронут.

## Явные ошибки переносимых путей

IDE ATM/Profi/Sprinter/SMUC ранее не закрывали ATA и не сохраняли актуальный
путь после создания локальной копии внешнего HDD. При следующем подключении
VMIDE мог снова указывать на исходный внешний образ. Теперь на disconnect
сначала закрывается ATA (фиксирует saved path), затем сохраняется относительный
VMIDE. Оригинал не изменяется. Неназначенный CMOS sidecar больше не открывается
с null-путём. Форматы CMOS/VMIDE и геометрия/протокол ATA не менялись.

Статический повторный просмотр путей не нашёл иных явных обязательных правок
в проверенных звуковых/host-компонентах. Обращения к AppData/реестру в них —
прежний необязательный **read-only импорт**, не место новых записей.

## Нагрузка — измерена, а не обещана

Отдельный process, affinity=1 только в диагностике; 50 warmup + 3×300 полных
CPU/video/audio кадров, два порядка сравнения. Runtime affinity не изменена.
Legacy control — тот же сохранённый старый класс в таком же тестовом bus.

| Нагрузка TSFM | Legacy, медианы (мс) | ymfm, медианы (мс) |
| --- | --- | --- |
| Idle/reset | 487,56; 517,77 | 538,49; 544,16 |
| Все 6 FM-каналов активны | 929,03; 916,30 | 556,36; 562,01 |

Активный FM в этом сценарии быстрее примерно на 39–40%. Idle на 5–10%
медленнее, абсолютная разница 0,09–0,17 мс/кадр: точное ядро продолжает
считать время и при выключенном выходе. Это ограниченный локальный benchmark,
не обещание ускорения любого приложения/ПК и не измерение GUI/audio latency.

## Что не проверено / ограничения

- Реальный запуск OmniPlayer 1.0.73 с NedoOS, ручное прослушивание, физические
  карты и сравнение записей hardware/ZXTune. Не заявляется «полностью одинаково
  с настоящим железом» или «звучит лучше» без слушательской проверки.
- TFM-файл отдельно не дан; не проверен. Полное покрытие CSM/3-frequency/SSG-EG,
  каждой огибающей/ключа/ошибочного порта не выполнено. Native core содержит
  эти модели, но наличие реализации не равнозначно полной проверке интеграции.
- Таймер/BUSY native bridge пока идут по аудио-квантам (около 22,7 мкс при
  44,1 кГц), не по каждому Z80-такту. Пин таймера/IRQ не перепроектировался.
- MIDI virtual GM не превращён в аппаратный SAM2695; прежние пределы GS/MIDI
  и других карт не устранены этой заменой OPN.
- Другой физический ПК/USB/FAT/exFAT, DPI/мониторы, realtime audio latency,
  все игры/модели и внешний recorder не проверены. Windows/.NET 4.x,
  x86 native зависимости (и optional DirectX/XNA по выбранному host) остаются.
  Нет обещания запуска на любом ПК или отсутствия любых Windows/driver traces.
- Старый известный CPU NMI prefix-boundary дефект вне этого этапа.

## Комплект и откат

`release` — полный runtime; Full/Clean ZIP содержат только его, включая Test,
музыкальные DLL/банки/ROM. Clean убирает только активные root sidecars.
`baseline-v87` — точная копия прежнего runtime. `source` — совмещённый исходный
ZIP с pinned OmniSound, отдельный OmniSound ZIP и обе verified Git-истории.
`diagnostics` — протоколы, manifest SHA256 и disposable test runtimes;
`checkpoints` — сведения о контрольных сохранениях.

Не смешивать DLL разных сборок. Для отката закрыть v88 и взять целиком прежнюю
папку/архив v87 или принятой v84; собственные Data/Saves сохранить отдельно.
Дальнейшую рабочую основу выбирает пользователь после проверки этой v88.
