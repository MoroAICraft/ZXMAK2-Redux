# v80 — безопасная оптимизация на базе v79

## Что изменено

Единственный изменённый runtime-компонент: `ZXMAK2.Engine.dll`.
В `src/ZXMAK2.Engine/BusManager.cs` ссылки на необязательные интерфейсы
тайминга ULA/CPU определяются при подключении устройств, а не повторно
через `as`/`is` в каждом цикле, обращении к памяти и порту.
Смена ULA/профиля обновляет ссылки; Disconnect/Clear сбрасывают их.
Результаты тайминга, множители частоты, WAIT, карта памяти и значения портов
остаются живыми. Порядок вызовов, такты и набор событий не сокращаются.

Все остальные runtime-файлы побайтово взяты из опубликованной v79.
Отдельный эксперимент `SndOut class -> struct` отвергнут: не показал
устойчивой пользы, один сценарий Evo замедлился. Финальная Hardware.dll и её
исходник совпадают с v79. Изменения DirectSound из старого dirty checkout
сохранены отдельно и не входят в v80. Этап улучшения качества звука не начат.

## Как проверено

- Все девять внешних probe: keyboard (565), golden rendering (7), contention/
  floating bus (46), INT/NMI (41), WAIT/AVR/COM/DOS (197981), video timing
  (12748), tape clock, SD lifecycle (22), PentEvo profile — PASS.
- Встроенные Test: `/hostfoldersd`, `/moonsound`, `/omnisound`,
  `/multisoundmax`, `/omni-opl`, `/master-volume`, `/evo-display` — PASS.
  В них проверены цифровой FM/PCM, ROM/RAM, физическое отключение портов,
  stereo/DOSEN paths, SD dirty/save/discard/refresh/export/close/relocation.
- Обычный опубликованный Test.exe с ULA sanity и benchmark — PASS.
- Два старых probe адаптированы, не ослаблены: tape mock реализует нынешний
  ITapeDevice и находит runtime machines.config; VideoTiming вручную подставлял
  private m_ula, обходя Add/Connect, и теперь зеркалит этот тестовый setup
  также для новой ссылки интерфейса (с очисткой при legacy switch).
- Сборка решения Release прошла. SHA256 движка из неё совпадает с tested DLL:
  `530D4D088E511710168F033B8F4EAF82D14E9A89EFB51EA2EB61FE6D7E9D434E`.
- Full/Clean ZIP проверены по SHA256 каждой записи (58/55 файлов). Чистый
  ZIP распакован в отдельную disposable папку: `/hostfoldersd`, `/moonsound`,
  `/evo-display` повторно PASS именно из упакованного runtime.

Функциональное сравнение выполняется отдельно от замеров: на каждый кадр
хешируются CPU-регистры/такты, весь video/PCM, в конце RAM; наблюдатель
хеширует адрес/значение/handled/tact памяти и портов. Сценарии: три snapshots
Pentagon, Spectrum48/128, Evo 3.5/7/14 MHz и смена профиля туда/обратно на
том же bus. В disposable harness RAM детерминирована, поскольку штатная
модель намеренно рандомизирует RAM при включении; её поведение не менялось.
Хостовые пользовательские SD/IDE источники удалены из test config; реальные
пользовательские носители/установки не затрагивались.

Финальные десять fingerprints v79/v80 совпали побайтово (final-*-state.txt).
Дополнительно запущена настоящая NedoOS с копией SD и неизменённым diagnostic
OmniPlayer 1.0.32: отдельный MoonSound и OmniSound, холодный старт и повторный
запуск плеера — OPL3/OPL4, Yamaha ROM, RAM 1024 KB обнаружены. Для OmniSound
плеер дошёл до рабочего файлового интерфейса. MoonService menu tests и
прослушивание реальной дискеты в этом этапе НЕ выполнялись; automated FM/PCM
и service detection routines не выдаются за эти ручные проверки.

Трасса реального MoonSound/gp: #0CBE=3E при DOSEN=True; чтение #00C6,
PC=96E1, available=True, handled=False->True, value=06; следующее #06C4,
PC=96E6, value=00. OmniSound/gp: #0CBE=3E, #00C6=00, #00C4=00, оба
available=True/handled=True при DOSEN=True. ROM Copyright читается через
PCM #C2/#C3; screenshot MoonSound 08.png подтверждает Yamaha ROM/RAM,
11.png — повторное обнаружение OPL3/OPL4. CSV и screenshots лежат в
diagnostics/nedo-moon и nedo-omni. Фактический clock=4 (14 MHz); это не
полноценный прогон NedoOS на 3,5/7 MHz — эти скорости проверены отдельно
в differential и Evo RAM workload.

## Замеры и ограничения

Используется неизменённый опубликованный Test.exe v79 (private helpers через
reflection), 500 кадров, прогрев и пять повторов в каждом из двух обратных
порядков. Evo: 300 кадров, три повтора каждого множителя 1/2/4 на порядок.
Не измеряется время создания машины/профиля. High priority, x86.
При финальном сравнении только дочерний harness закреплён за CPU affinity 1:
на i7-14700KF неприкреплённые прогоны имели сильный разброс. Сам эмулятор,
Test.exe, глобальные приоритеты и настройки питания не менялись.
Предварительные/отвергнутые прогоны сохранены отдельно, не выдаются за итог.

Медианы финального сравнения; положительное значение — сокращение времени:

| Сценарий | v79, мс | v80, мс | Сокращение времени |
| --- | ---: | ---: | ---: |
| testVideo, 500 кадров | 390 | 353 | 9,49% |
| zexall full, 500 кадров | 355 | 327 | 7,89% |
| testOutFe, 500 кадров | 417 | 377,5 | 9,47% |
| zexall light, 500 кадров | 278 | 251 | 9,71% |
| CPU-only контроль | 248 | 246 | 0,81% |
| Evo 3,5 MHz, 300 кадров | 1562,5 | 1571,5 | -0,58% |
| Evo 7 MHz, 300 кадров | 2414 | 2372,5 | 1,72% |
| Evo 14 MHz, 300 кадров | 3167 | 3078,5 | 2,79% |

CPU-only контроль не оптимизировался; отличия менее 1% (CPU/Evo 3,5) не
считаем доказанным ускорением/замедлением, они меньше разброса этих прогонов.
Evo workload — искусственная программа в RAM с видео/портами/цифровым mix,
не запуск произвольной игры или NedoOS-плеера. Полные выборки/min/max:
diagnostics/performance-summary.csv и paired-*.txt. Прогрев: 100 кадров в
встроенных сценариях, 30 в Evo. В этой таблице 10 измерений на встроенный
сценарий и 6 на каждый Evo режим. На других компьютерах выигрыш может отличаться.

WPR CPU profile недоступен (0xc5585011), системную политику не обходили.
Это статически выделенный участок и измеренная оптимизация, не заявление,
что инструментальный профиль нашёл все узкие места.

Непроверенные вручную вещи: длительное прослушивание музыки/игры с реальными
носителями, полный оконный/GPU backend и все исторические машины/профили,
физический VGA/джойстики. TS-Conf/ATM Turbo 2 ещё не реализованы этим этапом.
Совпадение тестов не является доказательством отсутствия любых будущих ошибок.
