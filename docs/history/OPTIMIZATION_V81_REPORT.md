# v81 — второй проход общего движка, база v80

## Область изменений

Только `ZXMAK2.Engine.dll`, исходники BusManager.cs и EventManager.cs.
Аппаратные модели, CPU opcode implementation, рендеры, звуковой тракт,
частоты/WAIT, SD lifecycle, клавиши и native chips не изменяются.
Рабочие компоненты D:/release80_sound_test совпали с v80; пользовательские
конфиги скопированы для контроля, оригинальная установка и её SD не изменялись.

1. Служебные timing hooks подключаются лишь для поддерживаемых контроллером
   интерфейсов. Без ICpuClockBusSync эти callbacks всегда были identity/no-op.
   Для Evo они остаются подключёнными постоянно, включая максимум текущей
   частоты: не отключаются при 14 MHz и не требуют переподключения для 3.5/7.
   Живые отношения частот/карты/значения/очерёдность событий не кешируются.
2. Семь приватных таблиц по 65536 callback slots полностью очищаются и
   используются повторно при Clear, вместо семи новых больших массивов.
   Не сохраняется ни одна старая подписка. Динамическое подключение/порядок
   multicast/handled/open bus остаются прежними.

## Диагностика до изменений

PhaseCostProbe: coarse timing frame boundaries/mix, отдельно callback counts.
Это не ETW/sample CPU profile и не полная стоимость рендера: значительная
часть рисования вызывается при чтении/записи памяти/портов. WPR был недоступен
при первом проходе; повышение прав/изменение системных политик не применялись.

Pentagon zexall, 20 кадров: 472898 sync, 177861 refresh, 391125 memory-complete
вызовов при отсутствии controller. Identity A/B на disposable VM: исходный
~309–316 ms, без заведомо пустых hooks ~292–294 ms, 500 кадров, обратный порядок.
Это диагностический эксперимент, а не полноценный реальный OS workload.

Mix готового звука: примерно 0.4–0.7 ms на 100 кадров в двух старых тестах;
малый вклад здесь не оправдывает вмешательства в звуковой тракт. На Evo
с пользовательским TSFM+MoonSound профилем значительный boundary cost дают
нативные звуковые чипы (в частности SAA): не отключаем их ради benchmark,
не меняем synthesis/filtering в этапе движка.

Отдельный proxy 100 полных перерисовок неподвижного кадра: Pentagon 9.017 ms,
Evo 8.908 ms; копирование 81920 pixels 100 раз: 0.443/0.460 ms. Это не стоимость
инкрементального рисования во время CPU bus access и не Windows/GPU backend.
Рендер/копирование не переписывались: подтверждённого безопасного кандидата
этот ограниченный замер не дал (buffers-v80.txt).

Контроль reload: 20 повторных подключений одного профиля ~558–560 ms,
gc0=70/gc2=35. Первичный кандидат ~465–510 ms, gc0=42–45/gc2=12–16;
окончательный обратный прогон: медиана 578 -> 486.5 ms (-15.83% времени),
gc0 70 -> 43, gc2 35 -> 14; по 8 измерений каждой версии (paired-setup-*).

## Проверки

Все 9 существующих внешних регрессионных probe, 7 встроенных device modes
и обычный Test.exe прошли. Добавлен RoutingSafetyProbe: 458800 проверок
no/legacy/live controller; переключение с max обратно на меньшую частоту;
Disconnect/Connect; очистка каждой из 7 таблиц (всех 65536 slots), отсутствие
старых callbacks, порядок multicast и open-bus values.

Functional observer/timing experiments выполняются отдельно от performance.
Основной bounded benchmark использует неизменённый Test.exe, High priority,
affinity 1 лишь для дочернего harness; сам эмулятор и power policy не меняются.
Пары проходят в двух обратных порядках. Source/снимки/носители только копии.

Все десять fingerprints CPU/RAM/video/PCM/I-O/tacts v80/v81 совпали точно,
включая Spectrum48/128, Pentagon snapshots, Evo 3.5/7/14 и переход профиля
туда/обратно на одном BusManager. Observer не участвует в speed benchmark.

Не скрываем отрицательные результаты: на Evo устойчивое ускорение не доказано.
Наблюдались малые отличия до ~2%, включая неизменённый CPU-only контроль;
диапазоны повторов перекрываются. Не выдаём их ни за прирост, ни за доказательство
нулевой стоимости изменений на любом ПК. В этой конфигурации TSFM+MoonSound
нативный синтез включён, а все реальные timing callbacks Evo сохранены.
Эти показатели сравниваются только с v80 данного прогона, не с другими датами.
Полные min/max/выборки — performance-summary.csv/paired-*.

Реальная нагрузка: исходный ROM + настоящая NedoOS + unmodified diagnostic
OmniPlayer 1.0.32 + `gp /bin/browser/example.pt3`. Снимок подтверждает
ProTracker 3/AY/TurboSound replay, воспроизведение до 00:33. Выполнено 500
кадров, прогрев 50, три повтора, affinity 1/High только child harness,
без port trace wrappers и peak telemetry внутри измеряемого цикла.
Медианы 6074 -> 5998 ms (~1.25%), что не считаем уверенным выигрышем без
более широкой серии. Цифровой PCM peak=606 и hash=A6C7A1A0BB664D0D совпали;
финальные PNG v80/v81 также совпали. Windows/аудиодрайвер и субъективное
прослушивание в эту headless проверку не входят. Фактическая NedoOS 14 MHz;
это не реальный OS/player test на 3.5/7, проверенных отдельно в fingerprints.

При проверке OmniSound первоначальный harness неправильно оставлял explicit
TurboSoundFmPro из пользовательского профиля. Omni BusInit запрещает такое
сочетание (`ZX OmniSound YM requires Internal Music: None`), поэтому получались
FF/необнаруженная плата. Та же ошибка подтверждена на v80 — не регрессия.
Исправлена только тестовая подготовка board:OmniSound: internalSound=None,
explicit AY/TSFM nodes удаляются, как при штатном UI-переходе. Эмулятор,
его validator и пользовательский конфиг D: для этого не изменялись.
Корректный сценарий OmniSound после холодного старта и повторного запуска gp
обнаружил OPL3/OPL4, ROM Copyright и рабочую SRAM; MS32=3E 02 00 01 A0,
clock=4. Logs `omni-repeat`/`omni-control` оставлены как INVALID configuration
diagnostics, не как принятый регрессионный прогон; принят `omni-valid-repeat`.

Из package runtime относительно контроля изменился ровно один DLL (плюс новый
README), проверено SHA256 остальных файлов. Engine.dll SHA256:
89C07730F1E54E8A6058F730E6E3566DD070925704ECB20517ACE14B980E02A2,
совпадает с DLL из полной сборки решения. Native dependencies взяты из v80.
Full/Clean ZIP созданы (58/55 файлов), SHA256 каждого entry совпал с runtime.
Чистый ZIP распакован в отдельную disposable папку: hostfoldersd/moonsound/
omnisound/multisoundmax/evo-display повторно PASS именно из упакованной сборки.

## Ограничения и откат

Длительное ручное прослушивание/игры, полный Windows/GPU backend и все
исторические машины не проверяются исчерпывающе. Новая TS-Conf/ATM Turbo 2
не добавляется. Ускорение теста не обещает тот же процент всем играм.
Улучшение качества звука — следующий отдельно согласуемый этап.

Контрольная v80 сохранена: bbf8e62 / zxmak2-v80-optimized, runtime/source ZIP
и обе history bundle находятся в исходном v80 пакете на L:.
Новый пакет отдельный; на GitHub ничего не публиковалось.
